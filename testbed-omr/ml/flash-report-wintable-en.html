Do We Need the AI? LinUCB vs a Rule-Based Baseline vs the Alternatives

29 October 2026 · Trace-driven evaluation on the calibrated link model · objective = goodput − 0.05·latency

To answer the reviewer's question directly, we put the LinUCB controller head-to-head with the obvious alternatives — including a hand-tuned rule-based controller (threshold rules on RTT/loss) — on the same states with the same calibrated goodput/latency model. All controllers choose a split; we score the real objective (goodput minus a latency penalty) and how close each gets to the best-possible action (oracle).

The honest headline

LinUCB matches or beats every baseline in all three condition sets, but the story is nuanced — and that nuance is the real finding:

  • The naive bonding (today's glorytun single-flow) and round-robin are clearly poor — any context-aware controller is a large improvement. So doing something smart is justified.
  • On clear-cut conditions (the real PSA trace, and single-SIM scenarios S0–S6), the rule-based baseline essentially ties LinUCB. When one SIM is plainly bad, a good threshold rule is enough — we do not pretend otherwise.
  • On ambiguous conditions (both SIMs partially degraded), LinUCB wins clearly (69% of oracle vs. rule/static well below, round-robin worst). When the right answer is a nuanced proportional trade-off across a multi-dimensional state, hand-tuned thresholds break down and the learned policy pulls ahead.
  • Static w=0.5 gets high raw goodput but pays a latency penalty (reordering across asymmetric RTTs), so it falls behind on the QoE objective — badly in the ambiguous set.

What this means for the paper (and for the advisor's critique)

The case for the AI is not "it beats a rule on every scenario" — it does not, and we report that honestly. The case is: (1) it matches the best hand-tuned rule without any manual threshold tuning, (2) it wins where thresholds are hardest (ambiguous, multi-degraded, non-stationary states), and (3) it keeps the latency-aware trade-off that pure-goodput splitters miss. The honest framing is "a learned policy that needs no per-condition tuning and degrades gracefully," not "a silver bullet."

Method & honesty notes

  • Trace-driven, model-based: all controllers are scored on the project's calibrated link model (link_model.evaluate), driven by the real PSA Agility Simba trace and by synthetic scenario/ambiguous states. This is a controller comparison, not a live measurement — a live testbed corroboration run is the next step.
  • Rule-based is a genuine, reasonable baseline (dead-SIM & weak-SIM thresholds), the same logic commercial heuristic bonding uses — so it doubles as a proxy for "commercial-style" splitting.
  • Objective is goodput − 0.05·latency (the controller's own reward); we also report raw goodput and latency so the trade-off is visible. On raw goodput alone, a fixed balanced split is competitive — stated plainly.
